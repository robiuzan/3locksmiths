# Dynamic presence — the doctrine

The full plan, its evidence and its phases live in **`docs/dynamic-presence-plan.md`**. This skill
is the part you must hold in your head while touching any of it. Business facts are in
`docs/business-facts.md` (§A.3, §B.5, §D.10 were written for this work); the calendar rules are in
`/israeli-calendar`.

## Five rules — none of them negotiable

1. **Every visible word ships inside `content/site.json` as real HTML.** Hidden elements or
   `<template>`, never JSON inside a `<script>`: `scripts/check-claims.mjs:27-34` strips scripts
   before matching, so a variant stored as JSON escapes every ⛔ rule. This is what keeps a topbar
   line inside check-claims, claims.mjs, check-typography, fix-links and phone.mjs.
2. **No clock, no network in the enrich chain.** CI re-runs `npm run enrich` and diffs
   `content/site.json` byte for byte (`.github/workflows/ci.yml:57-66`). Date selection happens in
   the browser in `Asia/Jerusalem`; copy changes happen through enrich + a human deploy. Never
   `Intl` in a pipeline script either — CI is Node 20, the workstation Node 24, and ICU output
   differs.
3. **Volatile chrome is excluded from `<lastmod>` and from snippets.** The root element of every
   live region carries the attribute `data-lm-ignore` (`scripts/lastmod.mjs` cuts those elements
   out before hashing) and `data-nosnippet`, both in the static HTML. **An attribute, not an HTML
   comment** — eight passes in the enrich chain re-parse the body with node-html-parser's defaults,
   which drop comments, so a `<!--lm:ignore-->` sentinel does not survive to `lastmod.mjs`.
   Without the exclusion one topbar edit re-stamps all ~105 sitemap URLs — the exact failure
   `lastmod.mjs:17-37` exists to prevent. The updates strip is deliberately **not** excluded: a
   new item is a real content change.
4. **Runtime input can only hide or select — never inject text.** The one runtime input is
   `status.json` (`{ mode: normal|quiet|reduced|off }`). If it is unreachable, slow (> 1.5 s) or
   malformed, fail **closed**: promos hidden, the evergreen line (and the header's own phone
   number, which no line replaces) always visible.
5. **No review, rating, count, badge, testimonial or "live stat" without a dated, sourced row** in
   `docs/local-presence.md` §3 — and no `Review`/`AggregateRating` markup ever (CI fails on it;
   Google gives no stars for self-serving reviews, widgets included).

Non-numeric files under `content/enriched/` are the right home: `check-freshness` treats them as
sources automatically (and `lib/live/*.mjs` since Phase 1), and `enrich.mjs` ignores them
(`/^\d+\.mjs$/`). `check-typography` also ignores them — so the ASCII-quote rule and the ⛔ claim
patterns for the registers live in `check-campaigns`, and `check-claims` sees the lines again once
they are rendered into `content/site.json`.

## The topbar

- It is the theme's own `.nav-main__top-bar` (109/109 pages, `display:none` at
  `public/wp-content/themes/gogo/assets/css/main.css:1008-1019`). Reveal it from `app/enrich.css`
  with a `body .nav-main …` selector — never edit `main.css`. Because it sits inside `.nav-main`,
  `nav.js` measures it and it rides the fixed header.
- **The reserve and the bar are one number.** `body .template-header` reserves what `nav.js` will
  measure: `84px + var(--live-bar)` on a phone (`--live-bar` is 34 px exactly when the bar is
  open), 160 / 180 px on desktop (126 / 146 + 34). Change the bar's height and the reserve moves
  in the same edit; re-run the pre-JS vs post-JS probe (memory `verify-pre-js-layout-headless`).
- **When it is open:** from 992 px (the sticky bar's cut-off) always — that band, iPad
  landscape included, has no other WhatsApp link; below 992 px only while a seasonal or safety
  line is live; on the
  **calm pages** (`data-live-calm` on the header — emergency ids 93xx and `/step/*`) a seasonal
  line is never rendered, so there the phone bar opens only for a safety line
  (`[data-live^="safety-"]` — which is why safety variants must carry that prefix).
- **How a line is revealed:** every line is a `<p data-campaign="…" hidden>`, the evergreen one
  last and not hidden. The head script writes `[data-campaign="v"]{display:flex!important}` and
  `[data-campaign="v"] ~ [data-campaign="evergreen"]{display:none}`. `!important` because the
  vendored bootstrap-grid.css ships `[hidden]{display:none!important}`; the sibling selector so
  that a page without line `v` simply keeps evergreen.
- One message at a time, one row (≤ 46 characters with the link label; evergreen ≤ 70, desktop
  only). **No ticker, no rotation, no `aria-live`** on it (WCAG 2.2.2; IS 5568).
- A line never types a phone number: `{phone}` prints and dials the call line from
  `site.config.json` (`topbar-call`), `{whatsapp:<label>}` links a word to the WhatsApp line
  (`topbar-whatsapp`), `link: { label, href }` is a page link (`topbar-link`). The
  `-call`/`-whatsapp` suffix is what the shared GTM container counts as `contact_click`; `-link`
  is deliberately not one. 100/101 stay plain text.
- **Do not repeat the header.** Hours and the phone number are printed right under the bar on
  desktop and in the sticky bar on a phone. The evergreen line is WhatsApp-only for that reason.
- The scraped text `שירות מהיר ומיידי` was an unquantified speed claim: replaced, never revealed.
- Every variant is short. Bytes in `bodyHtml` ship twice (HTML + RSC payload).
- Not built yet (Phase 2, with `live.js`): the ✕ dismissal, the `reduced` line and the
  `status.json` read. Do not render a `reduced` line before the switch that reveals it exists —
  text-only crawlers ignore `hidden`, and "reduced availability right now" on 109 pages is a
  sentence we do not want quoted.

## The seasonal card

- Native `<dialog>` + `showModal()`: top layer beats the z-index war (`.menu-toggle` 99,999,999,
  `.sticky-cta` 9,990, magnific 1,042) and gives focus containment, Esc and focus-return.
- Rules: never on first pageview from search; 2nd pageview or 20 s + scroll; never on the 93xx
  emergency pages, `/thank-you/`, `/step/*`, or any page with the 100/101 line; once per campaign per
  14 days; never on a quiet day or under `quiet`/`reduced`/`off`; **if `localStorage` throws, do
  not show**. Primary action is `tel:` (`popup-call`); never a form field.
- Title is a `<p>` with `aria-labelledby`, not a heading — CI enforces one `<h1>`, and a heading
  on 100 pages is outline noise. Injected only on pages where it may show (never a
  `data-live-calm` page), hidden, in a `data-lm-ignore` region with `data-nosnippet`.

## The updates strip

- Homepage only (the one reliably indexed page), restoring the theme's `.s-latest-posts` band. No
  per-item URLs while 22/105 URLs are indexed. Cards link to existing evergreen pages.
- Absolute `dd/mm/yyyy` dates, pre-rendered. Hides itself client-side when the newest item is older
  than 45 days (owner decision, 2026-09-29) — an old date reads as an abandoned site.
- Never a customer name, street, plate or face; city only; one week after the job; owner photos only
  through Media Studio (raw catalog originals are served with EXIF intact).

## Reviews — three states, in order, never skipped

| State | Precondition                                                                               | What ships                                                                                    |
| ----- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| A     | today: the 12 non-genuine reviews are being removed (§B.5)                                 | **nothing** review-related; the ask-flow runs off-site                                        |
| B     | ≥ 5 genuine reviews with a dated ledger row that matches the owner's dashboard             | text count + Google-issued links; no schema; re-keyed check-claims                            |
| C     | GBP API approved (≈ 2026-11-04 earliest) and the owner accepts Google's relevance ordering | live display via a same-origin route; ≤ 30-day KV; never git; attribution; `textContent` only |

Never bake Places or GBP review content into `site.json` or commit it — git history is permanent
storage and both terms forbid it. Never filter by stars. Never name the §G.1 characters.

## Precedence in the browser

`status.json` override → hard quiet day (memorial, fast, civic: evergreen only) → safety window
(on through Shabbat and chag — owner, 2026-10-01) → Shabbat/chag (evergreen, no seasonal line) →
seasonal window (highest priority wins; ties fail the build) → evergreen. Everything below the `status.json` line is resolved **at build
time** by `lib/live/compile.mjs` into a flat list of "show variant X from A to B" intervals; the
browser only looks up the interval that contains now. It re-runs on `pageshow` and
`visibilitychange` (and fires `resize` if the line changed, so `nav.js` re-measures the header),
arms one timer for the next boundary so a visible tab flips at sundown too, and honours
`?at=<ISO>` client-only for preview, e.g. `/?at=2026-12-06T10:00:00%2B02:00` (a frozen instant:
no timer).

## Gates you must leave green

`npm run build` runs `prebuild`: check-freshness, check-claims (the rendered `site.json`, so every
line), check-typography, check-campaigns (offsets and impossible dates, ⛔ claims and ASCII quotes in
the registers, tokens and no typed phone number, line length, live routes, the `safety-` prefix,
priority ties, windows that never show, **no compiled interval inside a hard quiet day and no
seasonal one inside a Shabbat or chag**, runway
≥ 30 days, calendar horizon, a source on every entry), the `node:test` schedule simulator (the
resolver, the compiled schedule and the **shipped inline script run in a VM** must agree on every
hour of the next 400 days and both sides of every boundary; DST 2026-10-25 and 2027-03-26; Adar
I/II in 5787; `site.json` carries the current script), and check-live-regions (no live region
inside `<main>`, none without `data-nosnippet`, no `<script>` in one, evergreen present, visible
and last, no seasonal line on a calm page). Then the CLAUDE.md §11 gate, then **verify on the live
URL** with `?at=` — never report done from the source.

## What you must never build here

A second `"use client"` component; a `functions/` folder (it deploys silently on the next
`-Confirm` and bypasses `_headers` and every gate — a PreToolUse hook warns); a GitHub Actions
deploy; a GTM Custom HTML tag; a third-party review widget; any "live stat"; any "recent job"
feed; any offer (§D.10); any variant stored as JSON in a `<script>`.
