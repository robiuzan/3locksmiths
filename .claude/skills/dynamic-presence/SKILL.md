# Dynamic presence — the doctrine

The full plan, its evidence and its phases live in **`docs/dynamic-presence-plan.md`**. This skill
is the part you must hold in your head while touching any of it. Business facts are in
`docs/business-facts.md` (§A.3, §B.5, §D.10 were written for this work); the calendar rules are in
`/israeli-calendar`.

## Five rules — none of them negotiable

1. **Every visible word ships inside `content/site.json` as real HTML.** Hidden elements or
   `<template>`, never JSON inside a `<script>`: `scripts/check-claims.mjs:27-34` strips scripts
   before matching, so a variant stored as JSON escapes every ⛔ rule. This is what keeps a topbar
   line inside check-claims, claims.mjs, check-typography, fix-links and phone.mjs.
2. **No clock, no network in the enrich chain.** CI re-runs `npm run enrich` and diffs
   `content/site.json` byte for byte (`.github/workflows/ci.yml:57-66`). Date selection happens in
   the browser in `Asia/Jerusalem`; copy changes happen through enrich + a human deploy. Never
   `Intl` in a pipeline script either — CI is Node 20, the workstation Node 24, and ICU output
   differs.
3. **Volatile chrome is excluded from `<lastmod>` and from snippets.** Wrap every live region in
   `<!--lm:ignore-->…<!--/lm:ignore-->` (stripped by `scripts/lastmod.mjs` before hashing) and give
   it `data-nosnippet` in the static HTML. Without the exclusion one topbar edit re-stamps all ~105
   sitemap URLs — the exact failure `lastmod.mjs:17-37` exists to prevent. The updates strip is
   deliberately **not** excluded: a new item is a real content change.
4. **Runtime input can only hide or select — never inject text.** The one runtime input is
   `status.json` (`{ mode: normal|quiet|reduced|off }`). If it is unreachable, slow (> 1.5 s) or
   malformed, fail **closed**: promos hidden, the evergreen phone line always visible.
5. **No review, rating, count, badge, testimonial or "live stat" without a dated, sourced row** in
   `docs/local-presence.md` §3 — and no `Review`/`AggregateRating` markup ever (CI fails on it;
   Google gives no stars for self-serving reviews, widgets included).

Non-numeric files under `content/enriched/` are the right home: `check-freshness` treats them as
sources automatically, `enrich.mjs` ignores them (`/^\d+\.mjs$/`), and `check-typography` must be
**extended** to read them (`scripts/check-typography.mjs:75`).

## The topbar

- It is the theme's own `.nav-main__top-bar` (109/109 pages, `display:none` at
  `public/wp-content/themes/gogo/assets/css/main.css:1008-1019`). Reveal it from `app/enrich.css`
  with a `body .nav-main …` selector — never edit `main.css`. Because it sits inside `.nav-main`,
  `nav.js` measures it and it rides the fixed header.
- **Before it ships:** a per-breakpoint `padding-top` reserve on `body .template-header` equal to
  what `nav.js` measures (topbar included). The header is `position:absolute` and covers the hero
  until JS runs (~8 s on mobile) — a pre-existing shift the topbar would enlarge.
- One message at a time. **No ticker, no rotation, no `aria-live`** on it (WCAG 2.2.2; IS 5568).
- Links carry `data-cta="topbar-call"` / `"topbar-whatsapp"` — the `-call`/`-whatsapp` suffix is
  what the shared GTM container counts as `contact_click`.
- The existing text `שירות מהיר ומיידי` is an unquantified speed claim: replace, never reveal.
- Every variant is short. Bytes in `bodyHtml` ship twice (HTML + RSC payload).

## The seasonal card

- Native `<dialog>` + `showModal()`: top layer beats the z-index war (`.menu-toggle` 99,999,999,
  `.sticky-cta` 9,990, magnific 1,042) and gives focus containment, Esc and focus-return.
- Rules: never on first pageview from search; 2nd pageview or 20 s + scroll; never on the 93xx
  emergency pages, `/thank-you/`, `/step/*`, or any page with the 100/101 line; once per campaign per
  14 days; never on a quiet day or under `quiet`/`reduced`/`off`; **if `localStorage` throws, do
  not show**. Primary action is `tel:` (`popup-call`); never a form field.
- Title is a `<p>` with `aria-labelledby`, not a heading — CI enforces one `<h1>`, and a heading
  on 100 pages is outline noise. Injected only on pages where it may show, hidden, inside
  `lm:ignore`, with `data-nosnippet`.

## The updates strip

- Homepage only (the one reliably indexed page), restoring the theme's `.s-latest-posts` band. No
  per-item URLs while 22/105 URLs are indexed. Cards link to existing evergreen pages.
- Absolute `dd/mm/yyyy` dates, pre-rendered. Hides itself client-side when the newest item is older
  than 45 days (owner decision, 2026-09-29) — an old date reads as an abandoned site.
- Never a customer name, street, plate or face; city only; one week after the job; owner photos only
  through Media Studio (raw catalog originals are served with EXIF intact).

## Reviews — three states, in order, never skipped

| State | Precondition                                                                               | What ships                                                                                    |
| ----- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| A     | today: the 12 non-genuine reviews are being removed (§B.5)                                 | **nothing** review-related; the ask-flow runs off-site                                        |
| B     | ≥ 5 genuine reviews with a dated ledger row that matches the owner's dashboard             | text count + Google-issued links; no schema; re-keyed check-claims                            |
| C     | GBP API approved (≈ 2026-11-04 earliest) and the owner accepts Google's relevance ordering | live display via a same-origin route; ≤ 30-day KV; never git; attribution; `textContent` only |

Never bake Places or GBP review content into `site.json` or commit it — git history is permanent
storage and both terms forbid it. Never filter by stars. Never name the §G.1 characters.

## Precedence in the browser

`status.json` override → quiet-day window → safety window → seasonal window (highest priority wins;
ties fail the build) → evergreen. Evaluate from windows that already carry ISO offsets; re-run on
`pageshow` and `visibilitychange`; honour `?at=<ISO>` client-only for preview.

## Gates you must leave green

`npm run build` runs `prebuild`: check-freshness, check-claims (extended to the registers and to
`out/`), check-typography (extended), check-campaigns (offsets, overlap with quiet windows, priority
ties, runway ≥ 30 days, calendar ≥ 12 months, business-facts citation, live routes, `data-cta`
suffix), the `node:test` schedule simulator (every hour of the next 400 days, DST 2026-10-25 and
2027-03-26, Adar I/II in 5787), and check-live-regions (no live region inside `<main>`, none without
`data-nosnippet`, no variant as JSON in a script). Then the CLAUDE.md §11 gate, then **verify on the
live URL** — never report done from the source.

## What you must never build here

A second `"use client"` component; a `functions/` folder (it deploys silently on the next
`-Confirm` and bypasses `_headers` and every gate — a PreToolUse hook warns); a GitHub Actions
deploy; a GTM Custom HTML tag; a third-party review widget; any "live stat"; any "recent job"
feed; any offer (§D.10); any variant stored as JSON in a `<script>`.
